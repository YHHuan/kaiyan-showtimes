# 開演 — 全台電影場次一頁查完

台灣已有幾種方便的電影場次服務，但想直接搜尋片名、影廳格式、地區，或查地方與藝文戲院時，
仍常要切換頁面、逐區點選或滑過整份片單。這個站把公開場次整合起來，
**按電影或按戲院查、支援複合搜尋、盡可能收錄未來場次與藝文館的特別放映**。

參考香港的 [wmoov](https://wmoov.com)。**不賣票、不收款**，點場次直接跳到該影城自己的訂票頁。

## 網站

<https://yhhuan.github.io/kaiyan-showtimes/>

不必下載也能用；支援 PWA 的瀏覽器可從站內「安裝到手機」，仍然是同一個零廣告、無會員的網站。

## 現在收了什麼

場次、影城、電影與涵蓋日期每天都會變動，最新數字由建置流程自動寫入
[`site-status.json`](https://yhhuan.github.io/kaiyan-showtimes/site-status.json)，不在文件硬寫一份很快過期的副本。

**連鎖影城**：秀泰（15 館）、國賓（9 館）、新光（5 館）、喜樂時代（4 館）、
美麗新、美麗華大直、威秀（含 MUVIE）、in89、樂聲

**地方・藝文・獨立・二輪**：光點華山、府中15、誠品電影院、光點台北、真善美、景美佳佳、
哈拉、總督、微風、百老匯公館、新莊麻吉、三重天台、王牌映画、日日新、親親

威秀官網有機器人防護，目前由開眼取得已公布的多日場次；王牌映画則是官網優先、開眼逐館逐日補缺。美麗華大直直接使用官方多日場次端點。

## 這個站特別想補上的使用空缺

- **幫我排**：指定最早開演、最晚散場、全票起價與距離上限，列出候選場次；支援跨午夜，片長未知時會明確提醒無法確認散場
- **查已公布的未來場次**：整合官方與開眼的多日檔期，並說明各館資料涵蓋範圍；未公布的日期不猜測
- **一部片在全台哪裡演**：不用一區一區切著查
- **影廳格式、語言與時段篩選**：IMAX、Dolby Cinema、Atmos、4DX、ScreenX 等可直接篩
- **免帳號收藏與行事曆**：頁首「我的收藏」查看電影、戲院與指定場次；收藏留在同一瀏覽器，單場可匯出 `.ics` 到 Apple、Google 或 Outlook
- **電影內容捷徑**：從單片頁前往 YouTube 預告、IMDb 與 PTT 討論，不把首頁變成新聞入口
- **電影基本資料**：有來源資料時顯示導演、主要演員、片長、分級與劇情簡介
- **策展・活動場單獨篩選**：《俠女》數位修復、《魯冰花》數位修復、映後座談、影展特別場——
  這類場次通常只在各館臉書零散公布，一般場次查詢工具不會收
- **只看還來得及的場次**：今天已開演的自動變灰，一鍵濾掉
- **同一部片不會被拆成好幾張卡**：各家把影廳規格和特別場名稱塞進片名
  （「DolbyCinema 藍色監獄」「蜘蛛人：重生日 經典美漫場」），這裡會歸戶回同一部片；
  但語言／版本（國語版 vs 日語版 vs 真人版）刻意保持分開，那是不同場次

「依時間找」的最晚時間早於最早時間時，代表隔日，例如 20:00–04:00 會納入隔天凌晨，
依實際日期與時間排序並標示「翌日」。有片長時用片長加 12 分鐘廣告估算散場；
無片長時只核對開演時間，行事曆也不擅自填入結束時間。
完整片名優先於地區解析，例如「台北物語」可搜尋全台，「台北物語台中」才加上台中條件。

電影歸戶保留加長版、導演剪輯版、動畫／真人版、語言及作品年份。抓取時保留來源電影 ID、原片名及來源片長；
metadata 會記錄實際匹配的來源片名與 ID，建站時再次核對；舊快取缺乏核對紀錄時不採用。部署會自動檢查比對版本，
必要時重新抓取電影基本資料；本機可執行 `node fetch/movie_meta.mjs --if-needed`。
已核實的同片異名可歸戶，例如「超異能快感2／超異能快感：魔法之書」。已知同名作品缺乏足夠辨識資料時，
明示「版本待確認」，不套用另一版本的海報與介紹；開眼搜尋同名多個電影 ID 也不取第一筆。

## 資料與自動更新

點頁首「開演・首頁」會回到預設查詢、清除篩選與定位，但保留收藏。
電影、戲院點「☆ 收藏」，指定場次點時間旁的 ☆；從「我的收藏」可以跨日期找回。
電影暫無場次或下檔後仍保留收藏；指定場次若過期或本輪資料未取得，會明確標示，
不把未取得資料推斷成取消，也不提供過期快照的購票連結。

收藏使用瀏覽器的 `localStorage`，不傳至伺服器、不需會員、不增加服務費用。
不同裝置、瀏覽器與網站網域各自保存，沒有自動同步；無痕模式結束、清除網站資料或
瀏覽器清理儲存空間時可能遺失。儲存被封鎖或容量不足時會提示失敗，不會假裝已收藏。
舊版電影／戲院收藏會保留，同一瀏覽器的多個分頁可接收收藏變動。

場次來自各影城官方公開的場次頁與 API，唯讀取得、單站間隔 250ms、失敗重試一次。
每筆場次都連回該影城自己的訂票入口。

GitHub Actions **每天台北時間 05:17 與 17:17** 各排程重抓一次，全程為程式抓取，不呼叫 LLM。
排程可能排隊延遲，抓取與驗證也需要時間，並非上述時間保證上線。
跨日可用性主要靠預先取得多日場次；若所選日期資料不足或更新失敗，頁面會列出缺口與官方查詢入口。

介面更新可手動勾選 workflow 的 `rebuild_only`，使用場次快取重建與發佈，仍須通過資料健康檢查與
瀏覽器測試；若電影基本資料快取尚未符合新版比對規則，會先自動重新取得。
預設不勾選；每日兩次排程仍會照常抓取所有來源。

部署、網域成本、自動更新、安全模型與事故處理詳見
[`docs/deployment-and-security.md`](docs/deployment-and-security.md)。目前是公開 repository + GitHub Pages，
使用標準 runner 的主機與排程成本可維持 NT$0；自訂網域是日後的品牌選項，不是上線必要條件。

### 壞掉的時候會怎樣

場次網站最危險的失敗不是整個掛掉——那看得出來——而是某家改版後解析器**安靜地回 0 筆**，
網站照樣產出、只是少了半個台灣。所以這條流程的重點都放在讓安靜的失敗變成吵的失敗：

| 情況 | 處理 |
|---|---|
| 單一來源抓取失敗 | 沿用上一輪快取的資料，頁尾標示「本輪未更新」 |
| 某來源筆數低於硬性下限 | 記錄異常，不計入健康來源總量；綜合總量與分館缺口決定是否中止發佈 |
| 某來源比上輪掉超過 55% | 標記警告，仍發佈但留下記錄 |
| 分館消失、只剩今天或某日期失敗 | 逐館健康檢查；官方／開眼逐館逐日選用，不用全來源總量掩蓋漏館 |
| 資料超過 72 小時沒更新 | 依來源與每筆快取時間排除；失敗備援不能被其他館的新時間「洗新」 |
| 全站總場次低於門檻 | **中止發佈**，線上維持上一版 |
| 過半來源異常 | **中止發佈** |
| 大比例分館沒有有效日期 | **中止發佈**，避免總量正常卻大量漏館 |

發佈走 GitHub Pages 的 artifact，不 commit 每日產出物，避免 repository 隨每天更新持續膨脹。
失敗時線上自動維持前一次成功的版本。

### 從雲端抓不到的來源

| 來源 | 本機 | GitHub Actions | 原因 |
|---|---|---|---|
| 秀泰、in89 | ✅ | ✅ | Cloudflare／Turnstile 對雲端 IP 沒有另眼相待 |
| 新光 | ✅ | 曾連線逾時，仍保留備援 | 已改抓新版 `/Sessions/Sessions?cinemaId=…`，不再等舊 API |
| 美麗新 | ✅ | 偶爾 403 | 官方站有時拒絕 GitHub Actions 雲端 IP |
| 王牌映画 | ✅ | ❌ | 官網從 GitHub runner 與公開雲端代理皆連線失敗 |
| 威秀（含 MUVIE） | ❌ | ❌ | 全站 Akamai，無頭瀏覽器同樣 403 |

這些來源使用**開眼電影網當安全網**，循頁面實際公布的日期連結取得多日資料。
官方與備援都會抓取，建站逐館逐日優先選新鮮官方資料，缺館、缺日期或失敗時才以備援補足；同一天不重複上架兩套來源。

### 為什麼流程裡沒有 LLM

抓取與解析全是決定性的程式，不該引入不確定性。唯一值得用 LLM 的地方是
**替新出現的場次標籤分類**（目前全站只有 99 種標籤，每週新增大概個位數）——
輸入有界、結果可快取、失敗時退回顯示原字串。這一步尚未實作，目前用規則表。

## 離我最近

點「離我最近」用瀏覽器定位，戲院改依直線距離排序。**定位只留在你的瀏覽器裡**，
距離全部在前端計算，位置不會送到任何伺服器（這個站是純靜態頁，也沒有伺服器可送）。

有座標的影城會參與距離排序：秀泰直接取官方 API 的經緯度、光點華山取官網嵌入地圖的座標，
其餘靠 OpenStreetMap 地理編碼。實際覆蓋數以每日 `site-status.json` 與網站結果為準。台灣的門牌資料在 OSM 覆蓋率不高，多數只查得到路名層級，
這種座標顯示成「約 N 公里」而非報到百公尺——排序夠用，但不假裝知道確切門牌。

## 授權與聲明

本站為非官方的場次整合，所有場次資訊的正確性以各影城官方公告為準。
片名、海報、劇情簡介之著作權屬各片商所有，此處僅作辨識與索引之用。

## 藝文館的未來檔期

一般場次查詢工具只給連鎖院線，藝文館往往只查得到「今天」甚至查不到。這裡的處理：

| 場館 | 來源 | 涵蓋 |
|---|---|---|
| 光點華山、府中15 | 官網 HTML | 官方檔期（府中15 可達次月） |
| 真善美戲院 | 官網 `/time` 的片單對照 + 各片場次頁 | 未來數日 |
| 光點台北 | 月曆是 JPG，但每部片另有文字版介紹頁 | 未來一週 |
| 國家電影及視聽文化中心 | 官網被 Cloudflare 擋，改走 **OPENTIX** 的節目 API | 最遠約一個月 |
| 誠品電影院 | 開眼多日場次 | 依來源實際公布日期，不只抓根頁的今天 |

TFAI 那條路值得記下來：**官網擋得死，但節目其實掛在 OPENTIX 平台上，那邊是 server-rendered**。
遇到擋爬的場館，先找它的售票平台往往比硬闖官網有效。

## 資料來源與立場

本站**只顯示場次時刻，不提供訂票、不處理付款、不嵌入任何影城的頁面內容**。
每一筆場次都連回該影城自己的訂票頁完成購票。

這個界線是刻意畫的。台灣公平交易委員會在 591房屋網 v. 豬豬快租一案的處分書
（[公處字第106084號](https://www.ftc.gov.tw/uploadDecision/6f9d8ac0-a5cc-4d99-80b5-27527d989cb1.pdf)）
中，把「僅摘取部分資料、詳細內容與交易仍須點回原站」的彙整服務明確列為合法對照組，
被裁罰的是把原站頁面**鑲嵌進自己介面**、使用者不必離開就能完成的做法。

其他自我約束：

- **不繞過任何技術保護措施。** 威秀影城全站有 Akamai 機器人防護，我們沒有嘗試規避，
  改用開眼電影網作為該連鎖的多日資料來源，仍以其實際公布範圍為限。
- 遵守各站 robots.txt，唯讀 GET，單站限速，不碰購票與會員流程。
- 非商業、無廣告、不收費。
- 每筆場次都標示來源影城；影城業者可透過 GitHub Issues 要求調整或移除。

**若您是影城業者**，希望調整或移除本站呈現的資料，請開一個
[Issue](https://github.com/YHHuan/kaiyan-showtimes/issues) 告知，我們會儘速配合。

> 這些是專案的自我規範，不是法律意見。本專案作者非法律專業人士。
