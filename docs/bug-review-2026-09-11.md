# 2026-09-11 海報裁切修正

## 原因與重現

海報以一張圖集（sprite）承載，每格 62×93 像素。首頁、單片頁原本各自建立裁切元素，
都使用原始像素位移；單片頁卻另以 `transform: scale(1.42)` 放大整張圖集，沒有同步放大位移，
因此非首格海報容易裁到相鄰電影，甚至同時露出數張圖片。

正式站《墜2》的海報索引為 18，應取來源矩形 `[496, 93, 62, 93]`；
修正前首頁正確，內頁卻取到約 `[349.30, 65.49, 61.97, 92.96]`。
手機首頁還有另一個問題：外框縮為 52×78，圖集仍使用原始大小，只顯示了海報的一部分。

## 修正

- 首頁與單片頁共用 `moviePoster()`，不再分別維護裁切邏輯。
- 圖片寬高與位移都用容器百分比，移除獨立的 `scale(1.42)`；大小改變時同步縮放。
- 沒有圖片或索引不合法時不建立海報，避免顯示其他電影。
- 保留原有圖集壓縮方式，不新增外部圖片服務、依賴或額外抓取。

## 驗證

`tests/posters.mjs` 使用多列彩色圖集，做 52 次來源裁切與截圖像素比對。
涵蓋首格、最右欄、換列、末格；首頁、點入內頁、返回列表、分享直連、重載與轉向；
320／390／1280px、1x／2x 裝置像素密度、非整數 CSS 尺寸及缺圖／錯誤索引。
這個測試在修正前可重現非首格內頁錯位。

`tests/smoke.mjs` 另核對每次部署的實際圖集與電影索引，檢查首頁及內頁的裁切矩形。
上述檢查已納入 `npm run smoke`，會和收藏、搜尋、跨午夜及電影版本測試一起執行。

## 範圍

本次修正的是顯示裁切，不會變更電影資料、場次、收藏或來源更新週期。
若首頁和內頁都顯示同一張錯誤海報，那是另一類來源／片名配對問題，仍須另外核對。
