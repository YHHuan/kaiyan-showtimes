## 仍待處理的可重現邊界問題

以下以現行函式及固定測試輸入重現，不代表目前每部上映電影都有問題；本次未修改這些規則。

| 優先 | 問題與觸發方式 | 原因／建議 |
|---|---|---|
| 高 | 「依時間找」選 1/1 的 20:00–隔日 04:00，1/2 01:00 場次沒有納入 | `filtered()` 先排除不是所選日期的資料；應改用含時區的起訖時間，納入相鄰日期 |
| 高 | 不知道片長的 13:00 場次，可能通過 18:00–23:59 篩選 | `planFits()` 將較早時間加一天，卻只在有片長時檢查截止時間；開始時間與估算散場都應各自檢查 |
| 高 | 同名的原版、加長版、導演剪輯版可能合併，共用不適當的片長或簡介 | `matchKey()` 會去除這些版本字串；實測「某部電影」與「某部電影 加長版」「某部電影 導演剪輯版」產生相同鍵。應保留版本辨識，補年份／來源電影 ID |
| 中 | 搜尋「台北物語」可能只找台北市，漏掉其他地區放映 | `parseSearchQuery()` 先從任意位置抽出「台北」當地區；實測得到 `text=物語, areas=[台北市]`。應先嘗試完整片名，再解析複合條件 |

## 收藏與來源的已知限制

- 收藏存在同裝置、同瀏覽器、同網站來源的 localStorage；沒有跨裝置同步。
- 無痕模式結束、使用者清除網站資料或瀏覽器清理儲存空間可能使收藏遺失；換網域也不會自動移轉。
- 電影收藏以顯示片名辨識。來源改名時可能暫時無法配對；保留原名紀錄，不用模糊比對自動改配另一部片。
- 指定場次若片名、戲院名、日期、時間、廳或版本改動，會標示本輪未查到。這也可能是來源抓取失敗，不等於取消放映。
- 場次每日兩次更新，收藏不是訂位，庫存與臨時異動仍須以戲院當下公告為準。
- 多分頁會接收變動並在寫入前重讀；localStorage 沒有跨分頁交易，極短時間內兩個分頁同時寫入仍有競態可能。

建議下一輪先處理跨午夜／未知片長，再處理電影版本辨識，最後調整完整片名的搜尋優先順序。
