# 開演 — 全台電影場次一頁查完

台灣的電影場次散在各家戲院官網，開眼電影網又只查得到「今天」。這個站把它們整合起來，
**按電影或按戲院查、看得到未來一整週以上、連藝文館的特別放映都收**。

參考香港的 [wmoov](https://wmoov.com)。**不賣票、不收款**，點場次直接跳到該影城自己的訂票頁。

## 這個站能做到、但別處做不到的事

- **查未來的場次**：開眼只有當天，這裡看得到下週末
- **一部片在全台哪裡演**：不用一區一區切著查
- **策展・活動場單獨篩選**：《俠女》數位修復、《魯冰花》數位修復、映後座談、影展特別場——
  這類場次通常只在各館臉書零散公布，一般場次查詢工具不會收
- **只看還來得及的場次**：今天已開演的自動變灰，一鍵濾掉
- **同一部片不會被拆成好幾張卡**：各家把影廳規格和特別場名稱塞進片名
  （「DolbyCinema 藍色監獄」「蜘蛛人：重生日 經典美漫場」），這裡會歸戶回同一部片；
  但語言／版本（國語版 vs 日語版 vs 真人版）刻意保持分開，那是不同場次

## 資料與自動更新

場次來自各影城官方公開的場次頁與 API，唯讀取得、單站間隔 250ms、失敗重試一次。
每筆場次都連回該影城自己的訂票入口。

GitHub Actions **每天台北時間 06:00 與 18:00** 各重抓一次（各影城多半在前一天 20:00 前
公布隔日場次，早上抓到完整的今天，傍晚補當天異動與新開放的預售）。

### 壞掉的時候會怎樣

場次網站最危險的失敗不是整個掛掉——那看得出來——而是某家改版後解析器**安靜地回 0 筆**，
網站照樣產出、只是少了半個台灣。所以這條流程的重點都放在讓安靜的失敗變成吵的失敗：

| 情況 | 處理 |
|---|---|
| 單一來源抓取失敗 | 沿用上一輪快取的資料，頁尾標示「本輪未更新」 |
| 某來源筆數低於硬性下限 | 判定解析器壞了，該來源整個排除，不讓殘缺資料上線 |
| 某來源比上輪掉超過 55% | 標記警告，仍發佈但留下記錄 |
| 資料超過 72 小時沒更新 | 該來源整個剔除，不拿三天前的場次騙人 |
| 全站總場次低於門檻 | **中止發佈**，線上維持上一版 |
| 過半來源異常 | **中止發佈** |

發佈走 GitHub Pages 的 artifact，不 commit 產出物——場次資料每天 4.7MB，
commit 進 repo 一年會膨脹到 1.7GB。失敗時線上自動維持前一次成功的版本。

### 從雲端抓不到的來源

| 來源 | 本機 | GitHub Actions | 原因 |
|---|---|---|---|
| 秀泰、in89 | ✅ | ✅ | Cloudflare／Turnstile 對雲端 IP 沒有另眼相待 |
| 新光 | ✅ | ❌ | `net::ERR_CONNECTION_TIMED_OUT`——連 TCP 都建不起來，研判是防火牆擋雲端 IP |
| 威秀（含 MUVIE） | ❌ | ❌ | 全站 Akamai，無頭瀏覽器同樣 403 |

這兩家改用**開眼電影網當安全網**（開眼有收它們，而且雲端抓得到），代價是只有當天場次。
新光的備援只在官方抓取失敗時才啟用，避免同一館出現兩份命名不同的重複資料。

### 為什麼流程裡沒有 LLM

抓取與解析全是決定性的程式，不該引入不確定性。唯一值得用 LLM 的地方是
**替新出現的場次標籤分類**（目前全站只有 99 種標籤，每週新增大概個位數）——
輸入有界、結果可快取、失敗時退回顯示原字串。這一步尚未實作，目前用規則表。

## 離我最近

點「離我最近」用瀏覽器定位，戲院改依直線距離排序。**定位只留在你的瀏覽器裡**，
距離全部在前端計算，位置不會送到任何伺服器（這個站是純靜態頁，也沒有伺服器可送）。

70 家影城中 66 家有座標：秀泰 15 館直接取官方 API 的經緯度、光點華山取官網嵌入地圖的座標，
其餘靠 OpenStreetMap 地理編碼。台灣的門牌資料在 OSM 覆蓋率不高，多數只查得到路名層級，
這種座標顯示成「約 N 公里」而非報到百公尺——排序夠用，但不假裝知道確切門牌。

## 授權與聲明

本站為非官方的場次整合，所有場次資訊的正確性以各影城官方公告為準。
片名、海報、劇情簡介之著作權屬各片商所有，此處僅作辨識與索引之用。

## 藝文館的未來檔期

一般場次查詢工具只給連鎖院線，藝文館往往只查得到「今天」甚至查不到。這裡的處理：

| 場館 | 來源 | 涵蓋 |
|---|---|---|
| 光點華山、府中15 | 官網 HTML | 官方檔期（府中15 可達次月） |
| 真善美戲院 | 官網 `/time` 的片單對照 + 各片場次頁 | 未來數日 |
| 光點台北 | 月曆是 JPG，但每部片另有文字版介紹頁 | 未來一週 |
| 國家電影及視聽文化中心 | 官網被 Cloudflare 擋，改走 **OPENTIX** 的節目 API | 最遠約一個月 |
| 誠品電影院 | 開眼（只有當天） | 官網全站 Cloudflare 硬擋，無替代管道 |

TFAI 那條路值得記下來：**官網擋得死，但節目其實掛在 OPENTIX 平台上，那邊是 server-rendered**。
遇到擋爬的場館，先找它的售票平台往往比硬闖官網有效。

## 資料來源與立場

本站**只顯示場次時刻，不提供訂票、不處理付款、不嵌入任何影城的頁面內容**。
每一筆場次都連回該影城自己的訂票頁完成購票。

這個界線是刻意畫的。台灣公平交易委員會在 591房屋網 v. 豬豬快租一案的處分書
（[公處字第106084號](https://www.ftc.gov.tw/uploadDecision/6f9d8ac0-a5cc-4d99-80b5-27527d989cb1.pdf)）
中，把「僅摘取部分資料、詳細內容與交易仍須點回原站」的彙整服務明確列為合法對照組，
被裁罰的是把原站頁面**鑲嵌進自己介面**、使用者不必離開就能完成的做法。

其他自我約束：

- **不繞過任何技術保護措施。** 威秀影城全站有 Akamai 機器人防護，我們沒有嘗試規避，
  改用開眼電影網作為該連鎖的資料來源，代價是只有當天場次。
- 遵守各站 robots.txt，唯讀 GET，單站限速，不碰購票與會員流程。
- 非商業、無廣告、不收費。
- 每筆場次都標示來源影城；影城業者可透過 GitHub Issues 要求調整或移除。

**若您是影城業者**，希望調整或移除本站呈現的資料，請開一個
[Issue](https://github.com/YHHuan/kaiyan-showtimes/issues) 告知，我們會儘速配合。
